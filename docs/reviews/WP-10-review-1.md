| 1 | MAJOR | `src/Signage.Web/Features/Player/PlayerEvents.cs:16-29` | The SSE loop only ends when `RequestAborted` fires or the subscription completes, and nothing ends it on app shutdown. Kestrel waits for these requests until `HostOptions.ShutdownTimeout` (30 s). I measured it: with one player connected, the app took 30 s to stop instead of 0 s. Docker's default grace period is 10 s, so `docker compose down/restart` and every image update in the office will end in a SIGKILL whenever any screen is online. Hosted services then don't stop cleanly and in-flight admin requests are cut off. ## Notes for the product owner
- Behind a reverse proxy, set `SIGNAGE__FORWARDEDHEADERS__KNOWNNETWORKS`. If it is left empty while forwarded headers are enabled, anyone who can reach the app directly can spoof their IP, which also affects the per-IP rate limits. The docs say this.
- Players reload themselves only when the reported app version changes, and today that version is `<Version>` in `Directory.Build.props` (finding 4b). Plan to bump it on every release.
- Problems a player reports (skipped videos and so on) go to the server log only, not to the admin UI (ADR-0010 §6).
